## 00. TL;DR（摘要）

一台从 电商平台A 购入的「正牌国际版」小米平板 5（nabu）在一次系统更新/OTA 失败后开机显示
**"The system has been destroyed"**，Recovery 同样报错，仅 Fastboot 可进。
排查发现该机为 **BL 锁定 + A/B 双分区俱损 + 国际版硬件** 的组合。

后续尝试解锁 BL 时，依次撞上小米服务器的**四道校验墙**：

| # | 错误码 | 含义 | 结果 |
|---|--------|------|------|
| 1 | **20045** | 账号注册地 ≠ 设备销售地 | 中国区账号 × 国际版设备 → **无解（区域出生即定）** |
| 2 | **20041** | 账号未关联手机号 | 补绑 +886 → **破解** |
| 3 | **20038** | 设备被另一账号通过「查找设备」锁定 | 登录 i.mi.com 移除设备 → **破解** |
| 4 | **20031** | 需在系统内绑定账号与设备 | 砖机无法进系统 → **物理墙，无解** |

**关键升级（v2）**：账号侧障碍全部拆除后，设备送**小米官方授权维修中心**尝试刷机——
**官方同样未能处理**。至此形成完整证据链：

> 民间免费软件路（20045→20031 四关）全灭 → **官方授权售后也刷不动** →
> 剩余技术出口仅为「拆机短接测试点 + EDL 9008 深刷」或「深刷线免拆机方案」。

**最有价值的教训**：

1. 「电商平台A 正牌国际版」实为**大陆硬件刷国际 ROM** 的机器（本次变砖的合理根因）——
   购买海外机型务必确认**原厂出厂区域 = 销售区域**（盒贴 NCC / 型号核对）。
2. **「修复」要分两个语义**：EDL 深刷救回的是**机器**，不是**资料**。
   Android 10+ 强制 FBE 全盘加密，userdata 绑定原机 TEE 密钥，
   任何「刷机保资料」承诺都受此物理限制——官方售后亦然。
3. 小米的防盗体系对「砖机」场景没有任何官方出口；这套体系防君子不防维修店，
   但确实把合法用户挡在了门外。

## 01. 故障现象与设备档案

### 1.1 设备档案

| 项目 | 内容 |
|---|---|
| 机型 | 小米平板 5（Xiaomi Pad 5） |
| 代号 | **nabu** |
| 版本 | 国际版（Global ROM），电商平台A 购入（卖家称正牌国际版） |
| 疑点 | 硬件疑为大陆版刷国际系统（见 05.4 根因） |
| 序列号 | b03****bb（fastboot 识别） |
| 当前槽位 | slot b |
| anti 版本 | anti: 1 |
| BL 状态 | **locked**（Device unlocked: false / critical unlocked: false） |
| Verity | true |

### 1.2 故障现象

- 开机 → **"The system has been destroyed"**
- 「音量+ + 电源」进 Recovery → 同样报错（Recovery 分区已损）
- 「音量− + 电源」进 **Fastboot**（兔子）→ 正常，可被电脑识别
- 变砖前征兆：OTA 更新中断/失败（用户回忆）

### 1.3 A/B 槽体检（fastboot getvar）

```
slot-retry-count:a = 6      slot-retry-count:b = 7
slot-successful:a  = yes    slot-successful:b  = yes
slot-unbootable:a  = yes    slot-unbootable:b  = no
current-slot = b
```

→ A 槽已标记不可启动，B 槽（当前）引导校验失败：**一次失败 OTA 把两个槽全部拖下水**。
尝试 `fastboot --set-active=a` → `FAILED (remote: 'Slot Change is not allowed in Lock State')`
——BL 锁定状态下连切槽这种零风险操作都被禁止。

## 03. 死锁模型：四重锁

小米 BL 解锁在 2025 年后实际由四道串联校验构成：

```
[设备] --① 区域校验--> [② 手机号关联] --> [③ 查找设备锁] --> [④ 系统内绑定] --> 解锁放行
        (20045)          (20041)           (20038)           (20031)
```

四道墙的性质不同：

- ①②③ 是**账号侧**配置问题 → 可通过换账号/补资料/云服务操作**逐个拆除**
- ④ 是**设备侧**物理依赖 → 要求设备能进系统，砖机场景**原理性无解**

本案例价值：把四道墙在一个砖机上全部实测了一遍，绘制出完整地图。

## 04. 救援时间线（错误码驱动）

### 4.0 排障（10-18）

- Mac 识别设备失败 → 排查出充电线冒充数据线 → 换线解决
- 确认 nabu / slot b / BL locked / A 槽 unbootable
- 切槽被 Lock State 拒绝 → 确认唯一路径是解锁 BL

### 4.1 第一关：20045（10-19 ~ 10-21）

- Windows 官方 MiFlashUnlock + 原中国区账号（+86 注册）
  → `20045 账号注册地和手机销售地不匹配`
- Mac miunlock 登录同一账号 → 服务器返回 `Account Region: CN`，dataCenterZone 默认 China
- 手动切 **dataCenterZone = Singapore** 再试 → **仍 20045**

**分析**：换服务器只改请求落点，不改账号区域属性。区域由**注册时手机号区号+网络环境**
在注册瞬间判定并写入账号档案（CN/Global 双数据中心架构，数据合规驱动），
**出生即定，不可自助迁移**。→ 换服务器路、老账号换绑本地手机号路，双双堵死。

### 4.2 第二关：20041（10-22）

- 注册全新本地区账号（+886 门号注册，Gmail 安全邮箱）
- miunlock 用新账号 → `20041 Sorry, your MI ID is not associated with a phone number`
- 经官方链接 `account.xiaomi.com/pass/serviceLogin?checkSafePhone=true` 补绑 +886 → **过关**

### 4.3 第三关：20038（10-22，本案例最精彩的反转）

- 重跑 miunlock → `20038 该手机已被账号 1*********2 通过查找手机锁定，无法解锁`
- 解读：**区域关、手机号关全部通过**；卡住的是老账号当年在机上开启的「查找设备」防盗锁
- 操作：登录 i.mi.com（注意 us.i.mi.com 与 i.mi.com 中国区入口的区别）→
  先在「设备管理」解除绑定 → 发现「查找设备」列表中 Pad 5 仍在
  （**解除账号绑定 ≠ 关闭查找设备**，两个独立开关）→
  在「查找设备」页对该设备执行移除 → 列表验证设备消失 → **过关**

### 4.4 第四关：20031（10-22，物理墙）

- miunlock → `20031 Please add your account in Settings > Developer options > Mi Unlock status`
- Windows 官方工具用新账号 → 同款提示（请绑定账号解锁）
- 含义：需在**平板系统内**完成「开发者选项 → 设备解锁状态 → 绑定账号和设备」
- 平板进不了系统 = 无法绑定 = **原理性死循环**：
  > 解锁工具需要设备活着 → 设备活着才能绑定 → 绑定才能解锁 → 解锁才能救活设备

### 4.5 EDL 软入口尝试（10-22）

- `fastboot oem edl` / `fastboot reboot emergency` → 无响应
- 关机 + 音量下 + 插线 → Windows 裝置管理員无 9008 设备
- 结论：nabu 锁定态下**软进 EDL 不可行**

### 4.6 官方维修中心处置（10-25，v2 新增）

- 设备送**小米官方授权维修中心**（**市，直营体系）尝试刷机
- 判定：**未能处理**
- 意义：此前 20031 关卡只证明「民间免费路无解」；官方中心的结果补上了最后一块——
  **授权售后体系对该砖机同样没有出口**。原因虽未公开（授权 firehose 区域限制、
  内部流程或固件库均属可能），但「送官方 = 唯一正解」的社会常识至此被实证推翻。

### 4.7 Mac 端 EDL 深刷 DIY 备战（10-25，v2 新增）

在等官方结果的同一天，民间路线完成全链路桌面验证（细节见 §07）：

- bkerler/edl 工具链跑通 + **patched firehose**（与官方 ROM 内置 firehose 同名同源）

## 05. 根因分析

### 5.1 账号区域体系

- 区号即国籍：+86 → CN 区；+886 → TW/国际区
- 判定发生在注册瞬间（区号 ★★★ / 注册 IP ★★ / 注册入口域名 ★）
- CN 与 Global 是**双数据中心**（数据合规驱动），账号档案不可跨区迁移
- Mi ID 为纯数字流水号，不含区域信息；区域是档案上的独立属性

### 5.2 四道校验的设计逻辑

防盗（防小偷秒解）× 防水货（防国行刷国际系统倒卖）× 数据合规。
隐含假设：**设备能开机**。

### 5.3 设计缺陷（本案例的核心论点）

- 砖机场景 = 无法进系统 = 无法完成第 ④ 关 → **合法用户被自己的防盗机制锁死**
- 民间 EDL 需拆机短接 + patched firehose；官方售后实测亦无出口（§4.6）
- 攻击面结论：这套体系防君子不防维修店，但确实把普通用户挡在了门外

### 5.4 原始故障根因（购机层）

「电商平台A 正牌国际版」大概率是**大陆硬件 + 刷入国际 ROM** 的改版机：
- 大陆版硬件的 OTA 服务器与刷入 ROM 不匹配 → 更新/校验失败 → 双分区俱损
- 也是 20045 的硬件侧根源（销售区域属性与账号区域天然错位）
- **购机防坑**：认盒贴 NCC 号 + 型号，问「原厂出厂就是国际版吗」

### 5.5 「修复」语义辨析（v2 新增，重要）

社区语境的「EDL 修复」**只指机器**，与资料无关：

- 标准线刷（MiFlash clean all 语义）写入**空 userdata 镜像** → 修好 = 出厂态
- Android 10+ 强制 **FBE 全盘加密**：userdata 是密文，解密密钥绑定原机 TEE 安全芯片。
  拆芯片直读、换机移植均得乱码（chip-off 取证在 FBE 时代已失效）
- 「保资料精刷」理论存在（EDL 下只刷系统分区、保留 userdata+metadata+persist），
  但对**双分区俱损的 OTA 灾难**而言：userdata 本身可能已损坏、刷写中途出错即两头空、
  metadata/persist 一旦误清密钥即失——三个风险叠加，成功率显著低于全清
- **给读者的现实预期**：变砖救援的合理目标是「救回一台干净的机器」；
  任何「保证资料完好」的报价都应追问其技术路径

## 07. Mac 端 EDL 深刷 DIY 完全记录（v2 新增，可复现）

> 本章为桌面验证记录（结案前未及实机执行），所有命令与环境已验证，
> 供后来者直接复现。全程 macOS 可完成，无需 Windows MiFlash。

### 7.1 工具三件套

| 件 | 来源 | 验证要点 |
|---|---|---|
| bkerler/edl | `git clone https://github.com/bkerler/edl` + venv | `edl.py --help` 可跑；依赖 pyusb/pyserial + brew libusb |
| patched firehose | Port-Windows-11-Xiaomi-Pad-5 releases：`prog_ufs_firehose_sm7150_ddr.elf`（724,800B） | **铁证**：官方 ROM 内置签名版同名（745,136B）→ 型号确认无误（SM7150=骁龙730G+UFS） |
| 官方 Global 固件 | `https://bigota.d.miui.com/<版本>/<文件名>`（bigota/bn.d/hugeota 三镜像同径） | nabu_global_images_V14.0.8.0.TKXMIXM（2024-01，最后 Global 稳定版）3.83GB，gzip -t + SHA256 校验，解包 77 分区镜像 + rawprogram/patch XML 6+6 |

### 7.2 下载工程教训

- bigota 对部分网络限速至 15KB/s（3.83GB 需数十小时）；**先测速再选镜像**
  （`curl -r 0-8388607 -w "%{speed_download}"` 三镜像实测，bn.d.miui.com 胜出 25 倍）
- aria2 16 连接后 27MB/s，3 分钟完成

### 7.3 线刷命令（等效 MiFlash clean all）

```bash
cd edl/
F=loaders/prog_ufs_firehose_sm7150_ddr.elf
IMG=firmware/nabu_global_images_V14.0.8.0.TKXMIXM_13.0/images
RP=$IMG/rawprogram{0,1,2,3,4,5}.xml   # 逗号分隔传给 qfil
PT=$IMG/patch{0,1,2,3,4,5}.xml

# 进 9008 后：先读后写
venv/bin/python edl.py printgpt --loader=$F       # 分区表可读 = firehose 接管成功

# 全包线刷（132 条目，sparse 自动展开，收尾自动 set bootable）
venv/bin/python edl.py qfil "$RP" "$PT" "$IMG" --loader=$F
venv/bin/python edl.py reset
```

源码审读结论（firehose_client.py / firehose.py）：
- `qfil` 接受逗号分隔多 XML，逐 `<program>` 条目按 `start_sector` 写入，
  **QCSparse 内建解包**（ROM 内 6MB sparse userdata.img → 12GB 空 ext4）
- 写完自动 `find_bootable_partition`（认 xbl/xbl_a）+ `setbootablestoragedrive`
- 单分区失败重进 EDL 重跑即可，幂等

### 7.4 进 EDL 的两条路（BL locked + 砖机）

| 路 | 操作 | 依据 |
|---|---|---|
| 深刷线（免拆机） | 关机 → 深刷线接平板+电脑 → **按线钮 5-8 秒** → 9008 | 触发机关在 XBL USB 枚举层；fastboot 可进 = XBL 活着。电商平台D「小米深刷線/EDL 線 9008」NT$100–350 |
| 短接测试点（拆机） | 屏面拆解 → 断电池排线（BN61）→ 测试点接屏蔽罩地 → 插线 | **nabu 测试点位置**：主板中央偏右、两块银色屏蔽罩间外露窄条上缘、紧邻橙色 FPC（丝印 M514m/MAPEC）上方，单颗镀金圆点。XDA #4553627 有**回形针短接成功**实证 |

### 7.5 风险与止损

- 拆机断排线：屏面缓慢开，**电池排线先断**
- patched firehose 被拒：回退 ROM 自带签名版；再不行走 bkerler/Loaders 找替代
- 误刷大陆包：只认文件名含 `global`（TKXMIXM）的包
- 保资料：刷前先 `edl.py r userdata out.bin` 抢救性备份（能否解开仍受 FBE 限制）

  2. 电商平台A 库存状态 JS 渲染，爬虫不可见（曾误报「在售」数小时，被用户抓出）
  3. 测试警报必须与真实警报在标题层就区分（曾用演示价 9,499 引发误会）

## 09. 经验教训（通用化）

1. **变砖救援的正确顺序**：先查 BL 状态（`fastboot oem device-info`）再谈刷机——
   locked 设备的一切 fastboot 写操作都会被拒，别浪费轮回
2. **错误码是地图**：小米解锁的每个 code 对应一道具体的墙，
   按码索骥逐关拆除，比网上泛泛教程高效
3. **「解除绑定」≠「关闭查找设备」**：i.mi.com 两个独立开关，20038 要关的是后者
4. **账号区域出生即定**：海外设备必须配同区账号；+86 号注册的账号救不了国际版
5. **砖机 + BL 锁 + 区域错位 = 民间软件路无解，官方售后也实测无出口（v2 实证）**，
   EDL 深刷是唯一技术出口
6. **「修复」救机器不救资料**：FBE 全盘加密 + TEE 绑定密钥，刷机路径天然清机；
   「保资料」承诺要追问技术路径并认清物理上限（§5.5）
7. **购机即避砖**：海外机型确认「原厂出厂区域」，
   验收三板斧：型号贴纸 + NCC 认证号 + 首开引导语言
8. **电商实时价只能点开那一秒确认**：比价快照用于发现线索，不用于决策
9. **官方标 ≠ 技术天花板**：授权售后的能力受授权账号/区域流程约束，
   民间 patched firehose 路线在部分场景反而更深（§4.6 + §07）
